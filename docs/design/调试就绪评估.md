回答三个问题：**解耦到位了吗、功能完备了吗、能进调试了吗。**

本文只做评估，不改代码。结论里的每一条都可以用仓库里的命令复现。

| 问题 | 结论 |

## 二、解耦：做到什么程度

### 2.1 边界由工程引用图定死

```
Core          → （无引用）           领域模型与计算，零第三方依赖
Contracts     → （无引用）           IMachineGateway / ITagMap / DTO
Device        → Contracts            OPC UA / Stub / File / Offline 四个网关
Sim           → Contracts、Core      磨削过程仿真
Nc            → Contracts、Core      R 参数生成
Data          → Contracts、Core      SQLite
Services      → Contracts、Core、Nc、Data      ← 没有 Device、没有 Sim
App           → Contracts、Core、Nc、Data、Services、Composition   ← 同样没有
Composition   → Contracts、Core、Device、Sim   ← 只有它认识硬件实现
```

**整个仓库里只有组合根一个地方认识 `OpcUaGateway` 这类具体实现。** 业务层与界面层
拿到的永远是 `IMachineGateway` 这个接口。

### 2.2 有测试盯着，不是靠自觉

| 守卫 | 断言的是 |
|---|---|
| `Core_does_not_reference_other_RollGrinder_assemblies` | 领域层不引用任何本仓库工程 |
| `Core_project_file_declares_no_package_or_project_references` | 连 csproj 里都不许出现引用 |
| `Core_does_not_reference_wpf_opcua_or_other_third_party_assemblies` | 领域层只用 BCL |
| `Application_services_do_not_reference_device_or_simulation_implementations` | 服务层看不见设备实现 |
| `App_assembly_does_not_reference_device_or_sim` | 界面层同上（读 PE 元数据，非 Windows 上也能查） |
| `Non_ui_assemblies_do_not_reference_wpf` | 除界面外没人碰 WPF |

Device 与 Sim 的网关实现类全部是 `internal`，只对 `RollGrinder.Composition` 与集成
测试可见——**即使有人给 App 加了引用，也 new 不出来**。

### 2.3 机床差异全在配置里，不在代码里

```
代码里出现 OPC UA 地址（ns=2;s=…）的次数：   0
业务层出现裸轴名（"X" / "Z1" / "U1" …）：   0
```

轴、行程、选装装置、阈值、工序类型码 → `machine.json`；
逻辑名 → 物理地址 → `tagmap.json`。代码按**角色**找轴（`MachineAxisRoles.Carriage`），
按**逻辑名**读写变量。换一台机床改两份 JSON，不动一行代码。

### 2.4 无机床开发的证据

**546 条测试没有一条需要真机床。** 唯一提到 `OpcUaGateway` 的测试只断言 DI 装配挑对了
类型，从不连接。

| 测试工程 | 条数 | 靠什么跑 |
|---|---|---|
| Core.Tests | 144 | 纯领域计算，连网关接口都不碰 |
| Nc.Tests | 24 | 假 tagmap |
| Integration.Tests | 378 | 仿真网关 + 临时 SQLite + 临时 config |

命令行 `--gateway sim` 让整套软件在工控机上脱机跑起来：仿真里有 r(z,θ) 辊面模型，
磨削会真的把余量磨掉，补偿三轮收敛 16.00 → 5.48 → 2.43 µm（直径量）——
**补偿闭环在没有机床的情况下是验过的。**

`--offline` 则是另一件事：**没有机床**时，自动磨削、手动、诊断三页整页关掉，
只留辊形编辑、工序编程、磨削记录、设置四页；顶栏标明离线。

### 2.5 一处有意为之

发布产物里同时带着 `RollGrinder.Device.dll` 与 `RollGrinder.Sim.dll`。这不是泄漏——
组合根需要它们，而且现场工控机上要能用 `--gateway sim` 脱机复现问题。App 程序集
本身不引用它们（有测试盯着）。

## 三、功能完备度

### 3.1 占位清零

以为还有。

### 3.2 对着两份基准逐条核过

| 基准 | 结果 |
|---|---|
| `机床硬件评估.md` P0（会磨坏辊或误导现场） | 2/2 ✅ |
| 同上 P1（与硬件不符） | 4/4 ✅ |
| 同上 P2（模型差异） | 3/3 ✅ |
| `模块切分与RGI对标评估.md` 13 项差距 | 13/13 ✅ |
| 六个页面的设计稿结构 | 全部实现（记录页 12 项指标 + 4 条曲线是最后补齐的一处） |

### 3.3 已知缺口

**一、Free（逐点）辊形类型。** RGI 有，我们没有。原因是结构性的：辊形段参数走
`ParameterSchema`，而 schema 是定长的一组 descriptor，装不下变长点列。补它要先给参数
模型加一种取值，影响面比"再写一个曲线类"大得多。

*现有替代*：辊形页可以把当前曲线**生成点列**导出，也可以**导入**一份点列作对照线叠着
看并报出最大相差。导进来的点列不会变成辊形——点列一旦能直接变成辊形，这条辊形就再也
说不清是按什么算出来的。

**二、U（辊形）轴行程留空。** 原理图没给。宁可不填，也不猜一个数写进去让人以为核对过。
现场量出来填进 `machine.json` 即可。

## 五、进调试前必须先有的三件事（都不在本仓库）

### 1. NC 侧按约定实现子程序与握手

上位机写下去的东西，NC 得认。需要 NC 侧实现的：

- **握手**：读齐 R 参数后看 `job.parametersValid`；工序参数**每个道次开始时重读**，
  不在作业启动时 latch（已于 2026-09 确认）；
- **工序专属参数块**：每道工序 8 格扁平数组，第 n 道第 i 项在下标 `n*8+i`，含义由同槽位
  的工序类型码决定。倒角 5 项、修整 3 项、探伤 1 项、圆度 2 项——**顺序就是协议**；
- **命令位边沿触发并自复位**：`manual.*`（27 个动作 + 5 个辅助循环）、
  `job.control.{jumpToStep,endStepEarly,cycleStart,feedHold}`。上位机写 true → 等脉宽 →
  写 false，**上位机被强制结束时那一句 false 可能发不出去**，所以自复位是最后一道保险；
- **机床报警**：`machine.alarm.{count,number[i],text[i]}` 三组要能读到。

### 2. tagmap 落到真实地址

样例里 102 个逻辑名的地址是**占位**（R[100..1127]、`"HMI_Cmd"."bitNN"`）。现场要按
PLC 与 NC 的实际分配改写。改完诊断页会立刻显示还缺哪几个。

R 参数号段已经排过并有测试逐个数过没撞：数组占 602 个 R 号，标量另算。

### 3. 现场确认三处

- `Q64.2` 是否真的双重分配（油冷机 / 冷却泵）——若是，手动页按"油冷机"会同时启冷却泵；
- 是否有独立的砂轮修整器驱动（决定 `hasWheelDresser`）；
- U（辊形）轴行程。

## 六、上位机侧还没被验过的两件事

说清楚边界，免得现场撞上才发现：

**一、WPF 界面从未真正跑起来过。** 开发环境是 Linux，只能编译（`EnableWindowsTargeting`）
与发布，跑不了 WPF。`dotnet publish -r win-x64` 出得来 exe 与 config 样例，界面逻辑
也都有视图模型级的测试，但**第一次在工控机上启动会是真正的第一次**。
预计会撞上的是这类问题：XAML 资源键拼错（已有守卫逐个 XAML 核对）、字体缺失
（字体已嵌入）、1920×1080 之外的分辨率下布局。

**二、OPC UA 会话从未对着真服务器连过。** 值映射层（节点 ID 解析、缩放、状态码、
类型不符、时间戳）有 14 条单元测试；会话建立、订阅、重连这一段只能在现场验。

## 七、建议的开调顺序

1. **工控机上先 `--offline` 起一次**：确认界面能起来、字体对、分辨率合适、数据库建得出来。
   这一步不需要 NC 也不需要网络。
2. **再 `--gateway sim`**：把编程、辊形、下发、记录、报表整条链路走一遍，确认逻辑无误。
   仍然不需要机床。
3. **接上 OPC UA，先只读**：诊断页看变量监视，逐个核对 tagmap 的地址对不对、缩放对不对。
   这一步不写任何东西。
4. **再放手动页**：一个动作一个动作试，确认命令位边沿触发且 PLC 自复位。
5. **最后才是下发与自动磨削**：先空运行（不装辊）看 R 参数与工序流程，再上第一支辊。

前两步今天就能做。第三步起需要第五节那三件事先到位。
