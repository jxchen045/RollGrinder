# 页面切换规范

本文件是页面切换逻辑的**唯一基准**，与 `README.md`（版面与配色基准）并列。
实现见 `src/RollGrinder.App/Navigation/NavigationModel.cs`，规则由
`tests/RollGrinder.Integration.Tests/NavigationTests.cs` 守住。

---

## 一、为什么要重做

改之前的问题（都是现场会挨骂的那种）：

| 症状 | 后果 |
|---|---|
| 手动与辅助操作页**没有任何入口** | 整页进不去 |
| 辊形编辑只能从工序编程进，诊断只能从手动进 | 要去哪儿得先记住"从哪儿能过去" |
| 第 8 键"返回"走历史栈 | 同一个键，按下去的结果取决于你怎么来的——不可预测 |
| 主页上的"返回"栈空 | 死键：按了没任何反应 |
| 跳转键混在功能键里，位置每页都不同（F6 / F3 / F7） | 每换一页要重新找"出口"在哪 |
| "补偿设置"键跳到工序编程页 | 标签和目的地对不上，典型误操作来源 |
| 辊形/工序页改了一半切走 | 修改被静默丢掉 |
| 自动循环运行中还能改辊形、按"下发 NC" | 违反最高原则：参数下发后上位机不该再碰运行中的这支辊 |

## 二、参考的既有系统

因为本软件与 **SINUMERIK Operate** 共用同一块触摸屏，操作员在两套界面之间来回切，
所以导航模型直接对齐 Operate 的习惯，而不是发明一套新的：

- Operate 用 `MENU SELECT` 把软键条**临时变成区域菜单**（加工/参数/程序/诊断/调试），
  区域之间是**平的**，不存在"从诊断返回到参数"这种事 → 本软件的**区域菜单**同理。
- Operate 的 `RECALL` 只退**一级**，且只在区域**内部**退 → 本软件的**导航槽**同理。
- Operate 的 `MACHINE` 键从任何地方一键回机床画面 → 本软件的**返回主页**同理。

另外遵循 ISA-101（人机界面设计）里几条与导航直接相关的：层级不超过 3 层、
导航控件位置固定、主画面一步可达、不可逆动作先确认、任何画面都不能把人困住。

## 三、结构：一个主页 + 五个子页 + 每页一层子视图

```
         ┌──────────────────────────────────────────────┐
         │  第 1 层   自动磨削（主页 / 机床画面）        │
         └──────────────────────────────────────────────┘
              ↑ 区域菜单（左上角，任何地方一步直达）↓
  ┌──────────┬──────────┬──────────┬──────────┬──────────┐
  │ 工序编程 │ 辊形编辑 │ 手动辅助 │ 磨削记录 │   诊断   │   第 2 层
  └──────────┴──────────┴──────────┴──────────┴──────────┘
        ↓ 页内子视图（辊形库 / 程序库 / 变量监视 / 日志 …）
  ┌──────────────────────────────────────────────────────┐
  │  第 3 层   子视图（最深就到这里，不再往下钻）         │   第 3 层
  └──────────────────────────────────────────────────────┘
```

**主页不是菜单页，是机床画面。** 开机停在这里，磨削时也停在这里。

## 四、两个固定通道，位置永不移动

界面上只有两处能换页，都在屏幕的固定位置：

### 1. 左上角「☰ RGX」= 去任何区域

- 顶栏最左边那个深蓝块（设计稿里原本只是品牌标识）现在是**菜单按钮**。
- 任何页面、任何深度按下去，都弹出**六格区域菜单**：自动磨削 / 工序编程 / 辊形编辑 /
  手动与辅助 / 磨削记录 / 诊断。每格都有序号（1–6）、页名和**一句话说明里面有什么**。
- 当前所在的那格高亮并标「当前页」，点它只是关菜单——不会"重新进入"把正在编的东西刷掉。
- 点菜单外面或「取消」= 关掉，什么也不做。

> **为什么放这里**：位置固定、永远可见、不占功能键槽位、不动设计稿的 76 px 顶栏版面。

### 2. 右下角第 8 键 = 退一级（导航槽）

底部功能条仍是设计稿规定的 **8 个等宽键**，但职责重新划分：

- **前 7 格**：本页的功能键，由页面给出（不足 7 个补空位，**保证第 8 格永远在同一个物理位置**）。
- **第 8 格**：导航槽。深底色，和 7 个功能键一眼分得开——**这一格永远是"出路"，不是功能**。

导航槽的标签**永远写明按下去到哪儿**，所以它虽然随位置变化，却不是隐藏模式：

| 你在哪儿 | 第 8 键显示 | 按下去 |
|---|---|---|
| 主页根部 | **页面菜单** | 弹出区域菜单（主页没有上一级） |
| 子页根部 | **返回主页** | 回自动磨削 |
| 因任务跳转而来 | **返回 工序编程**（举例） | 回派你来的那一页 |
| 页内子视图里 | **返回 诊断**（举例） | 关掉子视图，回本页根部 |

**没有任何状态组合会让这个键变成死键**（`NavigationTests.The_navigation_key_always_has_a_meaning` 守着）。

## 五、五条硬规则

1. **区域之间是平的，不叠历史栈。**
   A→B→A→B 切一百次也不积累任何状态。"我在哪儿"只取决于现在，不取决于路径。
   这条消灭了旧实现里"返回键结果不可预测"的根源。

2. **导航槽一次只退一级，且标签说明退到哪。**
   子视图 → 本页根部 → 主页。没有"退着退着不知道退到哪"。

3. **最深三层，回主页永远一步。**
   任何位置按左上角菜单 → 自动磨削，一步到家。

4. **任务跳转只记一个返回点，办完即清。**
   唯一需要"回到我来的地方"的场景是 A 页派你去 B 页取个东西：
   - 自动磨削 →「补偿设置」→ 工序编程（导航槽变成「返回 自动磨削」）
   - 工序编程 →「选择辊形」→ 辊形编辑（导航槽变成「返回 工序编程」）
   - 手动与辅助 →「诊断」→ 诊断（导航槽变成「返回 手动与辅助操作」）

   只记**一个**返回点，不是栈；中途从菜单切去别处，任务作废，返回点清掉——
   不会把旧的返回点带到毫不相干的页面上。

5. **平切会清掉子视图与任务返回点，状态不残留。**

## 六、防呆

### 6.1 改了一半不许静默丢掉

辊形编辑、工序编程是编辑页。**脏页（顶栏显示「已修改」角标）要切走时，先弹确认框**，
三选一，每一项都写清后果：

| 选项 | 行为 |
|---|---|
| **继续编辑**（默认、主按钮） | 留在本页，什么也不做 |
| **保存并离开** | 保存成功才走；**保存失败留在本页并报警**，绝不假装走成了 |
| **放弃修改并离开**（红色） | 回到进入本页（或上次下发成功）时的状态，然后走 |

> 当前辊形库/程序库的存储还没接通，所以这两页 `CanSave == false`，
> 确认框**不显示**「保存并离开」——不给一个按了没用的按钮。接上存储后自动出现。

「放弃修改」是**真的回退**，不是只清个标记：两页都在进入时存了一份快照
（辊形存曲线段集合，工序存整支程序的参数文本），回退时按快照还原。

工序编程页的"脏"还有一层含义：**改了但还没下发 NC**。
所以下发成功后本页立刻变干净——界面和机床上的程序一致了。
这样操作员改完工序直接按「进入自动磨削」时，如果没下发就会被确认框拦住。

### 6.2 运行中锁编辑（对应最高原则）

自动循环只要还挂着程序（NC 通道状态 ≠ 复位），**辊形编辑与工序编程整页转只读**：

- 顶栏出现「运行中 · 只读」角标；
- 两页的编辑类功能键（保存 / 另存为 / 新建曲线段 / 点表导入 / 生成点列 / 轧辊数据 /
  **下发 NC**）变灰不可按；
- 但**页面照样能进、能看**——只读不是禁止访问。不把人困住，也不让人误改正在磨的这支辊。

### 6.3 其他

- **没有死键**：该禁用的键**变灰但保留在原位**，不让键位跳动；
  没接通的动作按下去记一条提示级报警，而不是假装成功。
- **浮层不夺焦**：报警仍然只走顶栏状态条，不弹模态框打断操作。
  只有区域菜单与离开确认这两个**由操作员主动触发**的浮层才会挡住页面。
- **标签即目的地**：跳转键的文字就是目的地页名（「磨削记录」「诊断」「进入自动磨削」）；
  名字是"东西"而不是"页面"的两个键（补偿设置、选择辊形）做成任务跳转，
  由导航槽的「返回 XXX」把人送回来。
- **触摸目标**：区域菜单每格 ≈ 350×136 px，戴手套也点得准。

## 七、键盘 / 操作面板软键

| 按键 | 作用 |
|---|---|
| `F1`–`F8` | 底部八格（`F8` = 导航槽）。**软键优先于输入框**：焦点在数值框里按 F 键也走功能条 |
| `Esc` | 有浮层先收浮层（等同「取消」/「继续编辑」），没有浮层则退一级 |
| `Ctrl+1` … `Ctrl+6` | 直接切到对应区域（顺序同区域菜单） |

---

## 八、切页时的状态保持

- 六个页面的 ViewModel **常驻**，切走不销毁：草稿、选中行、查询条件回来还在——误触的代价是零。
- 切走调 `OnDeactivated()`，切入调 `OnActivated()`；**只有当前页收到 `OnTick`**，
  刷新节拍 5–10 Hz，与机床数据到达频率解耦（不变）。
- 磨削记录页每次进入重新查询（数据在别处会变）；其余页保留原状态。

## 九、代码落点

| 关注点 | 位置 |
|---|---|
| 切换状态机（纯逻辑，无 WPF） | `Navigation/NavigationModel.cs` |
| 页面发起跳转的接口 | `Navigation/INavigator.cs` |
| 换页、确认、导航槽标签、菜单（唯一一处） | `ViewModels/ShellViewModel.cs` |
| 页面侧约定（7 个功能键 / 脏标记 / 只读锁 / 子视图） | `ViewModels/PageViewModelBase.cs` |
| 顶栏菜单按钮、面包屑、两个浮层、键盘映射 | `Views/ShellWindow.xaml(.cs)` |
| 规则守卫 | `tests/RollGrinder.Integration.Tests/NavigationTests.cs` |

页面之间**互不引用**：页面只说"去哪儿"，换页由外壳做。
新增一个页面 = 加一个 `PageKey` + 一个 ViewModel + 在组合根注册，
区域菜单、导航槽、面包屑自动跟上，不改导航代码。
