第一轮测试问题分析与修改稿

逐条回应测试中提出的 28 个问题：哪些是缺陷、根因在哪；哪些是设计问题、改成什么样。修改稿按"按键优先、触摸兼容、图形辅助输入、边编边校验"重新组织了辊形、工艺程序、作业、自动、手动、砂轮和配置七块，并给出分期计划和需要拍板的问题。

0结论

3 个缺陷已查到根因"启动不加工"是下发写错进给速度加仿真把进给 0 当成瞬间走完；库里重名是"另存为"不改名且不查重；显示对不上是辊形与轧辊各有一个长度。
测试意见大多成立28 条里：缺陷 7 条，设计需改 19 条，需现场确认 2 条。没有一条是"甲方理解错了"。
核心改动是数据分层轧辊、辊形、工艺程序、作业四样东西各管各的，作业只做"组合 + 下发"。这一条同时解决了辊形页和工序页的大部分意见。
先修缺陷，再改结构阶段 0 修缺陷约 2 天，可以马上做；阶段 1–3 的结构改动要等第 7 节几个问题拍板，尤其是工控机面板类型。

1测试数据里查实的问题

数据来自甲方测试后的 D:\RG-Demo：数据库里有 2 个辊形、2 个程序、2 个作业、3 条磨削记录，日志无报错。

缺陷 1 · 启动后不加工（场景 3①）

三条磨削记录都在开始后 3 秒就判为"已完成"。这支辊有 9 道工序（开始、短行程、粗磨、半精磨、精磨、光磨、测量、圆度、结束），参数都在合理范围，不是参数乱设导致的。两个缺陷叠在一起：

  1. 下发时写错了通用进给速度。代码注释写的是"取首道磨削工序的进给"，实际取的是第一道工序。这支辊第一道是"开始"，没有进给，于是写给 NC 的 job.feedMmPerMin = 0。真机上引用这个变量的 NC 程序会拿到 F0。五轮自检下发的程序第一道是"测量"（有进给），所以一直没暴露。
  2. 仿真机床把进给 0 当成瞬间走完一刀。拖板停在 0 位不动，每一拍都判为"到端点换向"，31 刀在 3 秒内刷完，然后报"循环正常结束"。

另外，上位机也没发现"比预计时间快了几十倍"这种不可能的情况，所以运行时没有任何提示。修改：进给取第一道真正走刀的工序；仿真按每道工序自己的进给走，非走刀工序给固定停留时间；增加"磨得比预计快得离谱 / 慢得离谱"的合理性报警；下发前校验每道走刀工序进给大于 0。

缺陷 2 · 库里同名条目（辊形 1②③、程序同样）

辊形库两条"工作辊-凸度300"，程序库两条"Test"，都是两秒到两分钟内先后存进去的。原因："另存为"不要求输入新名字，直接拿当前名字存一条新的；库也不检查重名。修改："另存为"弹出命名框、默认"原名-副本"；库内名称唯一，重名时问"覆盖 / 改名 / 取消"。

缺陷 3 · 辊形显示与设置对不上（辊形 1⑥）

辊形里存的辊身长度是 300 mm（机床允许的最小值，编辑器的默认值），而曲线段区间填到了 100–800 mm，超出了辊形自己的长度；作业里这支辊却是 2000 mm。第二段锥度的区间 225–300 mm 和第一段 100–500 mm 还互相重叠。预览按 300 mm 画，所以和输入对不上。

根子在数据结构：辊形和轧辊各有一个长度，互相不知道；区间用"起点 / 终点"两个数，允许重叠和断开，也没有实时校验。修改见 5.2：Z 坐标 + 段长，自动首尾相接；辊形不再自带"真实辊身长度"，改为"设计长度"，选用时与轧辊长度核对。

2逐条回应

缺陷 程序行为错了；设计 能用但不合理，要改；确认 需要现场或甲方给出答案。优先级 P0 阶段 0 就修，P1 结构改动时一起做，P2 之后。

4五条设计原则

  1. 按键优先，触摸兼容。每个操作都能只用软键和方向键、翻页键、回车完成；触摸是加速手段，不是唯一手段。去掉所有下拉菜单：选项不超过 8 个用竖向软键，更多用可上下键移动的选择列表。版面固定"底部 8 横 + 右侧 8 竖"软键，和同屏的 Operate 一致。这一条要等问题 Q1 确认面板类型，但按它做，两种面板都能用。
  2. 图形辅助输入。凡是几何或运动参数，旁边配简图，当前正在输入的那一项在图上高亮，下面一行写说明、单位、允许范围。
  3. 数据分层，各管各的。轧辊（尺寸、重量、材质）、辊形（曲线）、工艺程序（工序序列）是三种可复用的基础数据；作业只是把三者组合起来下发。
  4. 边编边校验，错了存不进去。每次改动立即校验，问题就地标红并在状态条计数；保存、选用、下发都强制通过校验。
  5. 名称唯一，保存语义明确。"保存"只更新当前条目；"另存为"必须输入新名字；库内重名要问。

  • 段定义：起点 Z（仅首段）+ 长度 L，终点自动算；插入、删除、调序后自动重新接续，不会重叠或断开。Z 的原点（左端还是辊身中心）见问题 Q6。
  • 点表类型：表格录入 Z 与直径偏差，可从 CSV 导入；插值方式四选一：线性、三次样条、保形分段三次（不过冲）、平滑样条（可调平滑度，用于测量数据）。预览同时画原始点与插值曲线，并显示最大弦高误差。
  • 校验常驻：段长合计是否等于设计长度、参数范围、曲线在段界的连续性（跳变多少 µm）、点表点数与单调性；出错的格子就地标红，顶栏显示"有 N 处问题"；有错时"保存"变灰。
  • 保存语义："保存"更新当前条目；"另存为…"必须输入新名字；辊形名在库内唯一。
  • 去掉"新建曲线段"键（与插入重复）；补"下移""复制"；允许删到空。

5.8 机床配置与标签映射

  • 机床配置：按分组显示为表单：机床标识、轴（名称、作用、行程、是否存在）、选装装置开关、工件范围、阈值；每项带单位、范围和说明，改动即校验。
  • 标签映射：表格：逻辑名、NC / PLC 地址、数据类型、读写方向、说明、当前值与质量。可按名称搜索、只看缺失项；"试读"按钮单点读取验证地址。
  • 权限与安全：所有人可看；只有制造商可改；保存前自动备份原文件；每次改动写审计（谁、何时、改了什么）；保存后提示"重启上位机后生效"；提供"恢复上一版"。

阶段 0 已完成 · 2026-09-26

上表阶段 0 的各项都已做完，操作测试手册已按新行为更新（开头"本版改动"一框列出复测要点）。和上表不一样的地方：

  • 区间重叠只作提示，不报错。阶段 0 的辊形还是逐段叠加：主辊形铺满全长，端部锥度叠在上面，重叠正是这种用法；把重叠当错误，现有的每一条多段辊形都会变红、存不了。超出设计长度、断开（有一截没有任何段覆盖）、参数越界照计划报错。重叠 / 断开在阶段 1 改成"起点 Z + 段长、自动接续"后从结构上消失。
  • 重名时给"覆盖 / 改名 / 取消"，与上文一致；按"保存"时改的名字撞上别的条目，也走同一个框。

顺手补的几处（都是阶段 0 各项要真正能用的前提）：

  • 辊形页加"设计长度"一栏。原来藏着机床最小辊长 300 mm，加了"超出设计长度"校验后，不能改它就编不了任何实际长度的辊形。
  • 辊形页改区间、改参数时就地更新，不再每打一个字重建参数格——原来光标每打一个字丢一次，边编边校验没法用。
  • 工序页左栏加"校验"按钮，校验结果挪到轧辊数据下方；"校验"真正跑下发前那套检查（原来只看填没填）。
  • 仿真机床把光磨道也走完，合理性报警才不会在光磨多的程序上误报；库条目编号精确到毫秒，一秒内另存两次不再悄悄覆盖。
