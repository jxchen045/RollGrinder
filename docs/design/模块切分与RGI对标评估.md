# 模块切分与 RGI 对标评估

对标资料：《达宇重型数控轧辊磨床 RGI 控制系统操作说明书》，2023-02-15，共 34 页。
本文回答两个问题：**线划在哪**，以及**线以上还缺什么**。

---

## 0. 结论先说

1. **两大模块的线已经在了，不需要重切项目。** 线就是
   `IMachineGateway` / `ITagMap` / `MachineStateSnapshot`，架构测试也已经在守。
   要做的是**补四处漏**，不是推倒重来。
2. **真正的问题不是耦合，是"线以上"不完整。** 对着 RGI 逐屏比下来，
   缺的 13 项**全部落在与硬件无关的一侧**——这正是你要重点开发的那一半。
3. **最要命的三处**：辊形叠加编辑器的输出没有出口（编了等于白编）；
   没有程序库/辊形库，一切挂在作业下（不能复用）；仿真太薄，撑不起"无机床开发"。
4. 另有一个数据归属问题：`machine.json` 里混进了**现场标定值**
   （砂轮直径、基准盘直径、探头距离、对刀偏移……），这些换一次砂轮就变，
   得由界面按权限改，不该躺在配置文件里等人去编辑。RGI 为此专门有一个"设置"页。

## 一、线划在哪

### 1.1 两大模块

| | **工艺侧**（与硬件无关） | **设备侧**（与硬件有关） |
|---|---|---|
| 干什么 | 工艺编排、辊形编辑、校验、补偿计算、持久化、界面、记录、打印 | 把逻辑名变成物理地址上的读写 |
| 工程 | `Core` `Data` `Nc` `Services` `App` | `Device`（OPC UA / 文件回放 / Stub）、`Sim` |
| 认识什么 | 只认 `IMachineGateway` 与**逻辑名** | 认 OPC UA 地址、DB 块、Q/I 点 |
| 没有机床能不能跑 | **必须能** | 不需要 |
| 现在多少代码 | 约 11 000 行 | 约 1 500 行 |

`Contracts` 不属于任何一侧——**它就是那条线本身**：接口、DTO、逻辑名常量。

**装配只在 `Composition` 一处发生**，`--gateway opcua|sim|file|stub` 决定装哪个实现。
业务代码里不许出现 `if (isStub)`（架构约束 ②），这一条有测试守着。

### 1.2 一个容易划错的地方：`RollGrinder.Nc` 属于工艺侧

直觉上"跟 NC 有关的都是硬件"。但 `NcJobTranslator` 干的事是
**作业 → 一组带逻辑名的写入**，比如 `job.step.continuousInfeedRadiusMmPerMin[2] = 0.025`。
逻辑名到 `ns=3;s="HMI_Cmd"."bit13"` 的映射在 `tagmap.json`，由设备侧消费。

所以它是**纯函数**：同样的作业永远产出同样的写入列表，不碰网络、不碰机床、可全量单测
（现在 20 条）。它属于工艺侧，而且是工艺侧最该被测透的一块。

### 1.3 现状：线已经在了

```
App ──────────────┐
Services ─────────┼──→ Contracts ←── Device
Nc ───────────────┤       ↑          Sim
Data ─────────────┘       │
Core（不引用任何人）       └── Composition（唯一同时认识两边的地方）
```

已有的守卫测试：

- `App_assembly_does_not_reference_device_or_sim` —— 界面碰不到设备实现
- `Application_services_do_not_reference_device_or_simulation_implementations`
- `The_domain_stays_free_of_infrastructure` —— Core 不引用任何项目与第三方库
- `Non_ui_assemblies_do_not_reference_wpf`

**所以"解耦"这件事，结构上已经成立。** 下面说漏在哪。

## 二、四处漏

### 漏 1：`machine.json` 混了两类数据

现在一个文件里同时装着：

| 类别 | 例子 | 多久变一次 | 谁改 |
|---|---|---|---|
| **机床固有能力** | 轴与角色、行程、最大进给、选装装置、工序代码 | 装机时定，之后基本不动 | 厂家工程师，改文件（`machine.json`） |
| **现场标定值** | 砂轮直径、砂轮宽度、基准盘直径、基准盘位置偏移、金刚笔位置偏移、B 探头距砂轮中心/表面距离、对刀偏移、对刀方式、各项公差 | **换一次砂轮就变** | 操作工/管理员，在设置页上改（存数据库）✅ 已分开 |

RGI 把第二类单独做了一个"设置"页，16 项，带权限（必须是管理员）。
我们**连这些参数都还没建模**——`machine.json` 里现在只有第一类。

**这是数据归属问题，不是耦合问题**：标定值虽然描述硬件，但它的编辑、校验、
持久化、权限控制**全是工艺侧的活**。

**建议**：新增 `MachineCalibration`，**存数据库不存 json**（要带修改人与时间，
换砂轮是个要追溯的事件），界面上做一个设置页，按 `UserRole.Administrator` 开放。
`machine.json` 只留固有能力，升级时照旧保留。

### 漏 2：没有"离线模式"这个产品概念

`--gateway stub` 有，但那是个哑网关，不是一个**说得清的工作模式**。
现在没有定义：办公室电脑上没有 `tagmap.json`、连不上 NCU 时，哪些页面该能用。

**应该能用的**（不需要机床）：程序编辑、辊形编辑、记录浏览、打印、用户管理、设置。
**应该明确禁用并说明原因的**：自动磨削、手动动作、诊断的实时区。

**建议**：`--offline` 作为一等模式，顶栏挂一个"离线 · 编程模式"的标识。
页面不是灰掉就完了，要说清"离线模式不可用"，而不是让人以为软件坏了。

### 漏 3：辊形叠加编辑器的输出没有出口 ⚠️

`RollProfileSegment` 与 `CompositeRollProfile` 已经写好了（段、区间、叠加顺序、镜像），
`ProfileViewModel` 也有完整的增删改与预览，`CompositeProfileTests` 也在测。

**但是**：

```csharp
public sealed record GrindingJob(
    ...
    string ProfileTypeKey,        // ← 单一曲线类型
    ParameterSet ProfileParameters,
    ...
```

`GrindingJob` 只存**一条**曲线；`NcJobTranslator` 按单一类型采样；
数据库 `job` 表只有一列 `profile_type_key`；`ProfileViewModel` 里的 composite
只活在内存里，**没有任何持久化、也没有任何路径进入作业**。

**结果是：辊形页上叠出来的多段曲线，一离开这一页就没了。**

这恰好是 RGI 的核心能力之一——它的辊形编辑左侧就是一个**曲线列表**，
Taper + Sine 组合成锥度倒角、Polynom + Radius 组合成多项式过渡圆角，说明书里
明写"也可与锥、半径等组合不同倒角"。

**这是线以上最该先补的一处。**

### 漏 4：仿真太薄，撑不起"无机床开发"

`SimulatedMachine` 524 行，模型是：**匀速去料** `RemovalRateMmPerMinute = 0.06`
外加一点测量噪声。

它够跑通"下发—运行—完成"的流程，**不够支撑界面开发**——因为界面上最重要的东西
（五条曲线、圆度、偏心度、电流、磨前磨后对比、补偿收敛）它一个都产不出来。

要做到"与硬件无关的部分功能完整"，仿真必须从**流程桩**变成**工艺模型**。详见第四节。

## 三、对标 RGI：线以上缺什么

按 RGI 说明书逐屏比对。**硬件相关**一列指的是"要不要机床才能开发"，
不是"要不要机床才能用"。

| # | RGI 有 | 我们 | 要机床吗 | 优先级 |
|---|---|---|---|---|
| 1 | **程序库 / 辊形库**：程序(.GGP)、辊形(.GGS)、作业三者分开，各有列表与打开/新建/删除 | ✅ 已做（2026-09）。`roll_profile` 与 `program` 两个库各自有列表/打开/另存/删除；作业引用它们时复制快照，库里改了不动已磨过的记录 | 否 | ~~P0~~ |
| 2 | **辊形多曲线叠加** | ✅ 已做（2026-09）。`GrindingJob.Profile` 改成 `CompositeRollProfile`，下发与补偿都对合成后的整条曲线做；编辑器的参数与区间改动真的回写了 | 否 | ~~P0~~ |
| 3 | **自动磨削参数矩阵**：行=参数，列=工序，一屏看完；红色=当前工序，黄色=下一工序 | ✅ 已做（2026-09）。投影在 `StepParameterMatrix`（纯函数、可测），自动磨削页显示矩阵，工序编程页保留单工序视图——按"并存"定的 | 否 | ~~P0~~ |
| 4 | **登录 + 用户管理**：未登录所有按钮灰；三级权限；增删用户、改密码 | ✅ 已做（2026-09）。口令按 PBKDF2-SHA256 存（每账号独立盐、21 万次迭代），库里没有明文；未登录时 `HasAtLeast` 一律 false，登录浮层算进 `IsOverlayOpen`，所以功能键与页面点击自动不透传；出厂种下的管理账号**不带口令**，首次登录时由现场自己设 | 否 | ~~P0~~ |
| 5 | **设置页**：16 项现场标定参数，管理员权限 | ✅ 已做（2026-09）。15 项标定值存数据库（不在 machine.json 里），设置页参数格由 `MachineCalibration.Schema` 生成，管理员以上才改得动，每一项记谁在什么时候改的 | 否 | ~~P0~~ |
| 6 | **五种曲线**：参考 / 误差 / 圆度 / 偏心度 / 电流 | 辊形 + 误差 | 数据要机床，**图表不要** | **P1** |
| 7 | **磨削中改参数并即时保存** | 没有 | 要重新下发 | P1 |
| 8 | **工序跳转 / 提前结束** | 没有 | 要写 PLC 命令位 | P1 |
| 9 | **对中界面**：头架侧 / 尾架侧 分别记录 A、B、(A−B)/2、直径、Z、U1，两侧比较 | 有 `mountingErrorMeasure` 开关，没有界面 | 数据要测头 | P1 |
| 10 | **打印**：磨前/磨后数据、曲线打印预览 | **完全没有** | 否（打印机就挂在工控机 X120 那条线上） | P1 |
| 11 | **圆度**作为独立工艺步骤 | 只有 `Measure` | 否 | P1 |
| 12 | **暂停**作为工艺步骤（磨到这一步停下等人） | 没有 | 否 | P2 |
| 13 | **更换砂轮向导**（手动对刀 → 改回自动 → 校验误差） | 没有 | 否 | P2 |

### 我们有而 RGI 没有的

不是全面落后，几处我们更强，值得保住：

- **机床能力门禁**：装不了的工序不让编、更不让下发。RGI 没有这层。
- **参数模式（`ParameterSchema`）驱动界面**：新增一类工序只写一个实现类并注册，
  界面/NC/数据库都不动。RGI 的参数列表是写死的。
- **双语（zh-CN / en-US）+ 文案全部进 resx**，有测试守着不许硬编码。
- **单位纪律**：内部半径量 mm、界面直径量 µm，换算只在一处。
- **分层守卫测试**：RGI 这类系统通常靠约定，我们靠编译期 + 测试。

### 一处要调和的冲突

RGI 允许**磨削过程中修改工艺参数并即时保存**（改过的参数显示红色，"保存参数"按钮激活）。

这看起来撞上最高原则——但其实不撞，前提是说清楚：
**改参数 = 对那一道工序的 R 参数做一次新的下发，NC 在下一道次读取。**
上位机改完就脱手；进程被杀，NC 用最后一次收到的值把这支辊磨完。

**它不是一个实时通道。** 只要坚持这一条，这个功能可以做，而且现场很需要
（不然发现参数不对就只能停机重编）。

## 四、"与硬件无关的部分功能完整"要怎么证明

光说"解耦了"没用，得能验。提两条可执行的判据：

### 判据 1：结构

工艺侧的全部工程 + 全部测试，在**没有任何设备程序集**的情况下编译通过、测试全绿。
现有的 `AppAssemblyArchitectureTests` 已经守住了 App，建议再加一条把整个工艺侧集合圈进去。

### 判据 2：功能

一条命令跑通一支辊的完整生命周期，**全程不碰真机床**：

```
dotnet run --project src/RollGrinder.App -- --gateway sim
```

要能走完：
登录 → 设置标定值 → 新建辊形（叠 3 段：主辊形 + 两端锥度 + 倒角）→
新建程序（排 8 道工序）→ 建作业（绑辊形 + 程序）→ 校验 → 下发 →
自动磨削（参数矩阵随工序推进、五条曲线在动、中途改一个参数并保存）→
磨后测量 → 补偿计算并收敛 → 记录归档 → 打印磨前磨后报表。

**这条路径跑不通的地方，就是线以上还缺的东西。** 建议把它固化成一条集成测试。

### 仿真要做到什么程度

要支撑上面那条路径，`SimulatedMachine` 得产出这些（全部是工艺侧代码，与硬件无关）：

| 要产出 | 模型 |
|---|---|
| **辊形实测曲线** | 目标辊形 + 系统性偏差（热变形、砂轮磨损、机床几何）+ 随机噪声 |
| **圆度曲线** | 每个测点绕一圈 36 点；相位基准用 `I37.1` 头架圆周分度；叠一个偏心分量与一个三瓣形分量 |
| **偏心度曲线** | 安装偏心 → 正弦，幅值随 Z 缓变 |
| **磨削电流** | 与切深 × 拖板速度 × 工件转速成正比，叠砂轮磨损的缓慢上升与颤振时的波动 |
| **磨前 / 磨后** | 同一支辊两次测量，磨后应当收敛到目标辊形内 |
| **补偿收敛** | 补偿一轮之后误差要真的变小——这是验补偿算法唯一的办法 |

这几项之前讨论过（"测量曲线模拟模块"），现在有了明确的用途：
**它不是测试替身，它是开发与验收环境。**

## 六、要你拍板的三件事

1. **程序与作业要不要分开？** RGI 分（程序是可复用模板，作业是一次磨削）。
   分开更正确也更像现场的用法，但改动涉及数据库与下发链路。我建议分。
2. **磨削中改参数做不做？** 现场很需要，也不违反最高原则（见第三节末尾），
   但要接受"一道工序可能被下发两次"。我建议做，放第三批。
3. **参数矩阵要不要替掉现在的单工序视图？** 我建议**并存**：
   矩阵用于自动磨削监控（一屏看全局），单工序视图用于编程（一次专心改一道）。
   RGI 其实也是这么分的——编程界面是单工序 + 参数列表，自动界面才是矩阵。
