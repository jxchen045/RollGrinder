# 自动化测试说明：一键全量测试与测试闭环

> 目的：在你的 Windows 机器上**真的把界面跑起来**，逐模块、全流程地测一遍，
> 结果打成一个 zip 上传，由我分析、修复、再测，形成闭环。
>
> 为什么要这样：开发环境是 Linux，WPF 界面从来没真正渲染过。
> 「点补偿设置就崩」正是这个盲区漏掉的——只在运行时才暴露的错误，编译和单元测试都查不出来。

---

## 一、怎么跑

**前提**
- Windows 10/11，装有 .NET 8 或更高的 SDK（`dotnet --list-sdks` 能看到 8.x / 9.x / 10.x 任一即可；VS2026 自带的 10.0 可以直接用）；
- **源码是干净的这一版**：用 git（`git fetch` bundle + `git reset --hard`），或把源码 zip 解压到**空文件夹**。
  不要把新 zip 解压覆盖到旧目录上——解压只增不删，旧版本删掉的文件会残留下来与新文件撞车。
  脚本第 0 步会核对（有 git 看未跟踪文件，没有 git 对照 zip 里的 `SOURCE-MANIFEST.txt`），
  发现残留就列出文件与删除命令并停止，不再往下构建；
- 在**已登录的桌面会话**里运行（界面自检要真的弹出窗口；远程无界面会话、计划任务、服务里跑不了）；
- 建议屏幕分辨率 ≥ 1920×1080（界面按这个尺寸设计）。

**运行**：双击 `scripts\run-full-test.cmd`。或者在仓库根目录执行：

```
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\run-full-test.ps1
```

**跑的时候**：会依次弹出三次上位机窗口，自己点、自己切页、自己关掉。
**这期间不要动鼠标键盘**——自检不依赖焦点，但人为点击会打乱它正在验证的状态。
全程大约 5–10 分钟（构建约 1 分钟，单元测试不到 1 分钟，三轮界面自检各 1–3 分钟）。

**跑完**：屏幕最后一行会给出 zip 的路径：

```
请上传这个文件 / upload this file (x.x MB):
D:\Projects\RollGrinder\TestResults\RollGrinder-TestRun-20260923-153000.zip
```

把这个 zip 上传给我即可。

**常用参数**

| 参数 | 作用 |
|---|---|
| `-SkipBuild` | 已经构建过，跳过构建 |
| `-SkipUnitTests` | 只跑界面自检 |
| `-SkipUi` | 只跑构建与单元测试 |
| `-UiPasses sim` | 只跑某几轮界面自检（`sim` / `offline` / `en-US`） |
| `-SimSpeed 50` | 仿真时间倍率（默认 20，1–100） |

## 二、五个阶段

| 阶段 | 做什么 | 产物 |
|---|---|---|
| 0 环境 | 系统、屏幕、.NET、git 提交号与是否有未提交改动；**核对有无旧版本残留文件** | `environment.txt`、（有残留时）`stale-files.txt` |
| 1 构建 | `dotnet build`，警告即错误 | `build.log` |
| 2 单元/集成测试 | **逐个测试工程**跑：Core / Nc / Integration，共 620 余条 | `unit\<工程>.log`、`.trx`、`.failed.txt` |
| 3 界面自检 | 三轮，见下节 | `ui\<轮次>\...` |
| 4 汇总 | 每个阶段一行结论 | `SUMMARY.md` |
| 5 打包 | 整个目录打成一个 zip | `TestResults\RollGrinder-TestRun-<时间>.zip` |

## 三、界面自检（`--selftest`）

上位机 exe 内置自检模式。**测的就是要交付的那个 exe**：字体、资源、装配顺序和现场完全一致。

### 3.1 三轮

| 轮次 | 机床 | 范围 | 验证什么 |
|---|---|---|---|
| `sim` | 仿真（20 倍速） | 全功能 + 全流程 | 所有页面、所有功能键、一支辊从编程到出记录 |
| `offline` | 离线 | 全功能 | 离线时进不去的页是否被正确挡住、离线能用的页是否完整可用、下发是否被拒 |
| `en-US` | 仿真 | 渲染巡检 | 英文界面下每一页、每个子视图、页面菜单态都渲染得出来，没有缺失的文案 |

### 3.2 覆盖清单

| 套件 | 覆盖 |
|---|---|
| **Session** 登录与用户 | 启动即要求登录；种子账号 admin 首次登录必须设口令；空口令、两次不一致被拒；设口令后登录；用户管理：建账号、重名被拒、重置口令、**最后一个制造商账号删不掉**、删账号；签退后口令错被拒、重新登录 |
| **Navigation** 导航 | 7 个区域逐个 `Ctrl+n` 直达并渲染（**每一页第一次渲染都在这里，XAML 运行时错误会在这一步暴露**）；顶栏快捷键角标；页面菜单：F8 打开、软键条变身、F8 取消、☰ 开关、Esc 收起、用 F 键选区域；导航槽：返回主页、Esc 退一级；**任务跳转：自动磨削 →「补偿设置」→ 工序编程 → F8 返回**；子视图开关；脏页离开确认：继续编辑 / 放弃修改真的回退 |
| **PageSweep** 逐页逐键 | 每一页在默认状态下把 7 个功能键挨个按一遍；开了子视图就截图再关掉，跳到别页就回来。危险键（启动、跳步、提前结束、HMI 复位、下发）不在这里按，由专门用例按 |
| **Profile** 辊形编辑 | 每种曲线段插入一次并检查参数、校验、上移、删除；无名保存被拒；另存为 → 从库里调回 → 段数一致；删库里的一条；生成点列 CSV；导入对照线；导入垃圾文件被拒；取消文件对话框什么也不改 |
| **Steps** 工序编程 | 新作业；工序按槽排序；每种可用工序各加一道；机床没装的工序被拒；删工序；缺编号、几何非法的校验提示；全部默认参数能通过校验；程序步骤开关；轧辊数据：改、存、关、重开后还在；程序库：无名被拒、另存为 → 新作业 → 调回、删除；从辊形库选辊形与取消；离线时下发必须被拒 |
| **Settings** 设置 | 标定值列出；改一个值 → 保存 → 重载后一致；**换砂轮向导五步走完**（离线时停在第 2 步是预期）；中途取消 |
| **Manual** 手动与辅助 | 实时值；**每一个动作按钮**（需要确认的按两下）；测量取 3 点、保存、清空；对中取头尾、清空；HMI 复位清空报警；跳诊断并 F8 返回 |
| **FullFlow** 全流程（仅 sim） | 建作业（**测量 → 粗磨 → 测量 → 圆度**，开磨前/磨后测量与磨前/磨后打印）→ 校验 → **下发** → 进自动页 → 仿真开磨 → **运行中辊形/工序页只读、下发键变灰** → 实时值在变 → 5 种曲线 → 启动键按两下的确认流程 → 保持、冷却 → 提前结束预备后 4 秒自动撤销 → **磨完** → 编辑页解锁 → **自动打印磨前工艺单** → NC 报"循环正常结束"（仿真里是 R124=1）→ **记录自动收尾为已完成** → **自动打印磨削报告** → 已收尾的记录再按"完成"不会被改、不会多打一张 → 记录的 3 条测量曲线有数据 |
| **Records** 磨削记录 | 按日期查询；打开记录看 12 项指标与 4 条曲线；日报、月报；辊件台账；磨前/磨后报表预览并**点页面上的"打印"按钮**；导出 CSV |
| **Diagnostics** 诊断 | 连接与 tagmap 完整性；变量监视、机床配置、变量映射、审计日志、运行日志；导出快照；**整机备份并检查 zip 内容** |
| **SessionTail** | 签退后功能键全部不透传 |

一轮 `sim` 大约 200 步。

### 3.3 自动检查的界面问题

除了功能，每一页、每个子视图渲染时还自动查两类界面问题：

- **缺失文案**：本地化器把缺的资源显示成 `!Key!`，扫整棵界面树找出来 → FAIL；
- **按钮文字被截断**：按钮太窄装不下文字，或按钮被父容器裁掉一截 → WARN，并列出是哪个按钮、差多少像素。
  英文文案普遍比中文长，所以 en-US 那一轮尤其有用。

### 3.4 每一步怎么判

| 结论 | 含义 |
|---|---|
| **PASS** | 做完了，断言都成立，没有意外的报警 |
| **WARN** | 做完了，但冒出了**不在预期内的提示级报警**，或发现了**按钮文字被截断**——值得看一眼 |
| **FAIL** | 抛了异常 / **界面线程上出了未处理异常** / 冒出**不在预期内的错误级报警** / 断言不成立 / 超时 |
| **SKIP** | 前置条件不满足没做（例如键是灰的、离线没有记录） |

逐键巡检用"宽容模式"：在空白状态下乱按，业务校验类报警本来就该出现，只有"未预期的错误"和界面异常才判失败。

失败的那一步**一定会截图**；另外关键画面（每页首次渲染、菜单态、子视图、向导各步、报表预览、全流程各节点）也会截图。

### 3.5 安全闸

自检会按"启动"、按"复位"、给 admin 设口令、写记录。所以：

1. **只许对着假机床跑**：`--gateway sim`、`--offline`、`--stub`。接真机床（opcua）或回放（file）时**拒绝启动**；
2. **只许用自检专用数据目录**：`--data` 指向的目录必须是不存在的、空的、或者带 `.selftest-data` 标记的。指向现场数据目录会被**拒绝启动**；
3. 文件对话框自动应答到结果目录，**打印写成 XPS 文件，不会出纸**。

脚本每一轮都新建数据与配置目录（在 `TestResults\run-<时间>\ui\<轮次>\` 下），不碰仓库里的 `config\`、不碰现场的 `data\`。

## 五、单独跑某一轮（排查时用）

`ui\<轮次>\command.txt` 里就是完整命令行。也可以手动：

```
cd src\RollGrinder.App\bin\Release\net8.0-windows
RollGrinder.App.exe --gateway sim --sim-speed 20 --selftest --selftest-label manual ^
    --data D:\tmp\st\data --config D:\tmp\st\config --selftest-out D:\tmp\st\result
```

退出码：`0` 全部通过（含 WARN），`1` 有失败，`2` 参数错误或被安全闸拒绝，`3` 自检中途放弃（超时或运行器崩溃）。

## 六、自动化覆盖不到的

以下需要人或真设备，自检不替代：

- **触摸手感**：戴手套点不点得准、按键大小是否合适（截图能看布局，看不出手感）；
- **真打印机**：自检打印写成 XPS，验证了排版与分页，没有验证纸张、边距在真打印机上的效果；
- **真 NC / OPC UA**：自检只对仿真与离线；与 SINUMERIK 的会话、订阅、重连只能在现场验；
- **仿真与真机的差异**：仿真机床在下发"参数有效"时就直接开磨，不等循环启动信号，真 NC 会等。所以全流程里"启动"键只验证"按两下确认"的流程与请求能发出，不以它作为开磨的前提；
  仿真按 NC 约定实现了"循环正常结束"位（开磨清 0、走完最后一道置 1、被中止不置），并且和真 NC 一样把所有工序走完（余量磨完只是不再去除材料），测量这类无进给的工序不去除材料；
- **美观**：配色、对齐、字号是否好看——截图里我能看出明显的问题（重叠、截断、空白），细节仍需人看。

## 七、第一轮的教训：时区

第一轮在东八区的 Windows 上跑，20 个失败里 16 个是同一个时区 bug：记录页把本地日期按 UTC 偏移 0 构造时间，
**开发机是 UTC，所以单元测试全过**，到了东八区一查询就抛异常。现在：

- 本地日期 → UTC 区间只在 `Core/Time/LocalDays` 一处换算，时区作参数，单测显式用东八区验证；
- 守卫测试禁止再出现 `new DateTimeOffset(…, TimeSpan.Zero)`；
- 我这边每次提交前，整套单元测试另在 `TZ=Asia/Shanghai` 下再跑一遍。

## 八、闭环

1. 你：跑 `scripts\run-full-test.cmd`，上传 zip；
2. 我：读 `SUMMARY.md` → `selftest.log` 的每个 FAIL/WARN → 对照截图与 `app-logs` 定位 → 修复；
   同时区分**被测软件的问题**和**自检用例本身的问题**（自检代码也是第一次在真 Windows 上跑，头一两轮可能两种都有）；
3. 我：提交、推送、重新打 bundle；
4. 你：更新代码后重跑，直到 `SUMMARY.md` 的结论是 PASS。
