实现见 `src/RollGrinder.Services/Manual/`，规则由
`tests/RollGrinder.Integration.Tests/ManualCommandTests.cs` 守住。

## 一、27 个按钮全部是**离散命令**，没有"按住才动"

| 组 | 个数 | 动作 |
|---|---|---|
| 测量臂 | 8 | 外臂 A 放下 / 外臂 A 收起 / 内臂 B 放下 / 内臂 B 收起 / 双臂到轧辊 / 双臂归位 / 校测量臂 / 测量采样 |
| 尾架与套筒 | 4 | 套筒伸出 / 套筒缩回 / 尾架前进 / 尾架后退 |
| 头架、软着陆与其他 | 15 | 头架正转 / 头架反转 / 头架 + / 头架 − / 拨盘伸出 / 拨盘收回 / U1 轴归零 / 头架侧升 / 头架侧降 / 尾架侧升 / 尾架侧降 / 冷却水 / 砂轮启动 / 测砂轮直径 / 各轴归位 |

### 辅助循环（5 个，不在按钮矩阵里）

手动磨削 / 基准标定 / 砂轮修整 / 辊对中 / 回参考点。

与上面三组的区别：那三组是"动一下某个机构"，这五个是"**跑一段事先编好的
循环**"，所以挂在功能键上而不是按钮矩阵里。机制完全一样——脉冲命令位、
PLC 上升沿触发并自复位、自动循环挂着程序时不给按。

会切削或让各轴走全行程的四个（手动磨削、基准标定、砂轮修整、回参考点）
要按两下；辊对中只是测量，按一下就发。

> **上位机不在使能链里**（见机床硬件评估 §5）：这几下都只是**请求**，
> 真正让不让动由 PLC 的互锁说了算。自动页上的"循环启动"与"进给保持"同理。


### 与原理图核对的四处更正

| 此前 | 原理图上实际是什么 | 改成 |
|---|---|---|
| 尾架**夹紧 / 放松** | 这一组只有前进/后退两对 DO（尾架 Q67.2 / Q66.1，套筒 Q66.2 / Q65.3，另有 Q67.0），**没有夹紧/放松** | 删掉这两个按钮。顶紧力归液压系统，不是上位机的一个按钮 |
| 测量臂 **A / B** | DI I113.0–I113.7 标的是**外测量臂**收起·放下、**内测量臂**收起·放下，以及外测头 A / 内测头 B 压缩过量、保护限位左·右 | 改为「外臂 A / 内臂 B」——只写 A/B，现场得猜是哪一侧 |
| 头架**启动 / 停止** | **正转 / 反转**两位 | 拆成两个保持型按钮，两位都关掉才是停；两者互斥 |
| 软着陆**升 / 降**（一对） | **Q69.0–Q69.3**：头架侧升·降、尾架侧升·降 | 拆成两侧各一对，共四个。两端不同步就是在掰辊子，分开给才能一侧一侧看着来 |

**还没做进按钮的硬件**（图纸上有，目录里暂时没有）：磁分 `Q65.1`、纸带 `Q67.3`、
油冷机、中心架托瓦、偏心套。要加就是目录里加一行 + resx 一条文案 + tagmap 一个命令位。

**这里没有点动（hold-to-run）。** 点动属于实时控制回路，需要硬件使能与安全回路托底，
归机床操作面板与 PLC——上位机被强制结束时，按住的那个键就松不开了，
这正是最高原则要避开的事。

所以「头架 +」「头架 −」是**转速加减一档**，不是把主轴点着转；
「头架侧升／降」「尾架侧升／降」是**发一个到位命令**，不是按住才升。

## 二、三种命令形式

| 形式 | 怎么写 | 用在哪 |
|---|---|---|
| **脉冲 Pulse** | 写 `true` → 等一个脉宽（`hmi.json` 的 `manualPulseMs`，默认 300 ms）→ 写 `false` | 22 个动作 |
| **保持 Toggle** | 按开关写 `true` / `false`，状态可回读 | 冷却水、砂轮启动、头架正转、头架反转 |
| **本地 Local** | 不写机床 | 测量采样（走测量服务存一个测点） |

### 互斥的一对：头架正转 / 反转

打开其中一个之前，先把另一位写成 `false`，再写本位 `true`。

**顺序不能反。** 反过来会有一瞬间两位同时为 `true`；按这个顺序，中途被打断
（进程被杀、网关抛错）也只会落到"两位都 false"——也就是停机，安全的那一侧。

这一条是**防呆**，PLC 侧该有自己的互锁。

> ### PLC 侧按**上升沿**触发并自行复位（2026-09 电气侧已确认）
>
> 上位机在写完 `true`、还没写 `false` 时被强制结束，那一句 `false` 就发不出去了。
> 脉冲的收尾是**尽力而为**，PLC 的边沿触发与自复位才是最后一道保险。
> tagmap 样例里每个命令位的 `description` 都写了这一条。

## 三、四道门禁

按钮按下去之前依次问四件事，任何一条不过都**一个字节也不写**，并且说清楚原因：

| 检查 | 不过时 |
|---|---|
| tagmap 里登记了这个命令位吗 | 按钮**压暗**（留在原位，不跳动），ToolTip 说明缺映射 |
| 连上机床了吗 | 禁用 + 报警"没连上机床" |
| 自动循环还挂着程序吗 | 禁用 + 报警；**读不到通道状态一律当作在忙**——不知道机床在干什么就别乱动它 |
| 是危险动作吗 | 第一下只变红显示"再按一次"，4 秒内按第二下才真发 |

**这四道是防呆，不是安全功能。** 真正的联锁在 PLC，上位机只是不去按那个按钮。

### 运行中唯一放行的两个

- **冷却水** —— 磨削当中开关冷却水是正当操作
- **测量采样** —— 不写机床

其余 25 个在 `通道状态 ≠ 复位` 时一律禁用。

### 要按两次的六个

| 动作 | 为什么 |
|---|---|
| 套筒缩回 | 顶尖离开辊子端面 |
| 尾架后退 | 让几十吨的辊子失去一端支承 |
| 拨盘收回 | 轧辊没停稳就收拨盘 |
| 头架侧降 | 把辊子落到托瓦上 |
| 尾架侧降 | 同上 |
| 各轴归位 | 整台机床一起动 |

同一时刻只留**一个**待确认的按钮，免得两个红按钮并排让人按错；
4 秒内不按第二下自动撤销，免得一小时后的误触被当成确认。

## 四、按钮的四种样子

| 样子 | 含义 |
|---|---|
| 白底描边 | 可按 |
| 压暗 35% | tagmap 没登记这个动作 |
| 变灰不可按 | 机床在忙 / 没连上，ToolTip 说明原因 |
| **红底「再按一次」** | 危险动作等第二下 |
| **绿底** | 保持型动作正开着（按状态回读点亮，读不到就不亮，不假装关着） |

动作发出去之后，按钮矩阵上方闪一条「XXX · 已发出」，停 3 秒自己消失——
**不占报警条**，报警条留给真正的故障。

## 五、配置

### tagmap.json

每个动作一个布尔命令位，逻辑名 `manual.<动作键>`；保持型动作另有
`manual.<动作键>.state` 用于状态回读。样例把 26 个命令位排在
`"HMI_Cmd"` 的 bit0–bit25，4 个状态位排在 `"HMI_State"`——
**现场按自己的 DB 块改地址，逻辑名不要动**。

上位机写的是**命令 DB**，不是物理输出点：DB 位到 `Q` 点的映射归 PLC。
样例里每个命令位的 `description` 记了原理图上对应的 `Q` / `I` 地址，
方便电气照着接——那是给人看的注释，代码里一个物理点名都没有（架构约束 ③）。

没登记的动作按钮会压暗：**先接哪个就先映射哪个，不用一次全接**。

### hmi.json

```
manualPulseMs   脉冲宽度（ms），默认 300
```

### 仿真

仿真机床把 `manual.X` 的布尔写入原样回显到 `manual.X.state`，
所以四个保持型按钮在仿真里是真的会亮的——仿真机床就是这台"机床"，这不是假数据。
